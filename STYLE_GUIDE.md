# Style Guide

Rules applied by the writer agent. Edit this file to change voice and style — no code changes needed.

## Voice
- Write developer-to-developer, not vendor-to-customer
- No corporate attribution ("Vercel believes", "as the team puts it")
- Address readers directly where it helps; avoid second-person when describing systems

## Argument
- State the argument early; don't build to it
- Technical claims must be earned, not declared
- New concepts need one sentence of context before first use
- Code blocks need a setup sentence before them

## Structure
- No hype openings ("We're excited to share...")
- No summary conclusions ("In conclusion...", "To summarize...")
- Section headings should carry an argument, not just describe content
- Making the call sections should respect developer intelligence — no prescriptive "you should use X"

## Prohibited phrases
(Also enforced by the linter — see src/lib/linter.ts)
- simply, just, easy, easily, obvious
- leverage, utilize, synergy
- cutting-edge, robust, scalable, seamless
- delve, streamline, harness, industry-leading
